# 平台身份、服务流程与管理运维

本文描述当前代码实现。头歌妈妈使用暖纸色、深棕顶栏、珊瑚强调色和用户提供的头歌妈妈图形 logo 的用户端与管理端工作台。用户端只承担登录、选择课程或一键处理全部未完成作业、查看服务状态；管理员负责内部排障、模型配置、用量核对和账号准入。模型用量不是用户余额，当前没有支付结算或付费套餐。

用户端完成进度默认只展示每个请求目标的最新安排，正在排队或运行的记录全部保留；被新安排替代的旧结果收进默认折叠的历史记录。列表以课程、状态与带单位的进度为主，历史详情明确为当次结果，不声称旧失败仍在处理中。首页课程可安排状态、完成进度摘要与一键安排按钮使用相同的当前记录判断，旧失败不会覆盖后来的完成结果。历史展开状态在轮询和刷新进度时保留，退出账号后重置。分组只影响展示，不删除任务或修改执行状态；历史范围为个人 API 返回的近期记录，不宣称列出全部历史。

## 身份与个人数据分区

1. 用户提交头歌登录名和密码，Go 服务向上游核验。
2. 上游必须返回正整数 `user_id`；平台以此自动查找或建立本地身份，生成平台用户 ID 与独立 `tenant_id`。
3. 平台存储上游数字 ID、当前登录名、姓名、角色、状态和时间戳；不存储头歌密码、Cookie 或模型密钥。
4. 浏览器取得随机的站内 HttpOnly 会话 Cookie，上游客户端及 CookieJar 只留在服务端内存。
5. 个人任务 owner 从服务器当前身份产生，客户端没有指定 owner 或 tenant 的权限。

头歌账号就是本站账号，没有单独注册、本站密码、邮箱验证或密码重置流程。登录名与姓名只用于展示，不作为身份、租户或任务归属键。当前每人一个独立数据分区，不是包含多成员与组织角色的企业租户体系。

升级前按登录名 hash 保存的任务不自动认领。管理员也不能仅凭同名登录名把旧 owner 改成新身份；当前没有自动 owner 迁移工具。保留原数据库可以供管理员查历史，新的个人任务使用平台身份命名空间。

## 用户 API

所有业务响应使用 `{data, error, requestId}` envelope，下面的路径属于本站 Go 服务，不是上游原站接口。登录接口开放，个人业务读取、任务写入和管理操作需要有效会话。

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| POST | `/api/auth/login` | 校验头歌账号并自动建档；只接受 `login`、`password` |
| GET | `/api/auth/me` | 返回本人公开头歌资料与平台 `id / tenant_id / role / status` |
| POST | `/api/auth/logout` | 删除当前站内会话并清 Cookie |
| GET | `/api/service/today-summary` | 北京时间当日实际完成并核验通过的已关联学生数与题数，仅返回日期、时区和计数 |
| GET | `/api/question-bank/summary` | 已登录用户可读的全站已验证题库计数，仅返回客观题、编程题和合计 |
| GET | `/api/avatar` | 当前用户头像，固定官方来源与内存缓存 |
| GET | `/api/courses` | 本人课堂，默认 `status=processing` |
| GET | `/api/courses/:course/homeworks` | 所选课堂作业摘要 |
| GET | `/api/courses/:course/exercises` | 所选课堂在线考试及本人交卷、成绩开放状态 |
| POST | `/api/jobs` | 创建课程、全部课堂或兼容作业任务，202 返回任务标识 |
| GET | `/api/jobs` | 本人的近期服务任务摘要，不包含内部采集任务 |
| GET | `/api/jobs/:id` | 本人的任务状态和公开进度 |
| POST | `/api/jobs/:id/cancel` | 请求停止后续执行 |

课堂执行：

```json
{"scope":"course","mode":"submit","course":"COURSE","idempotency_key":"GENERATE_A_UNIQUE_KEY"}
```

全部活动课堂执行：

```json
{"scope":"all","mode":"submit","idempotency_key":"GENERATE_ANOTHER_UNIQUE_KEY"}
```

`Idempotency-Key` 请求头也可设置幂等键；如果 body 同时提供，二者必须相同。同一键用于不同 payload 会返回冲突；同账号相同目标的活动任务会复用。`course` 不允许 `homework_id` 或 `game`，`all` 不接受客户端指定的课堂、作业或 game。

兼容的整份作业请求为 `scope=homework`、`mode=submit`，需 `course` 与 `homework_id` 且不带 game。平台模式的公共 `/api/jobs` 接受 `submit` 和 `homework / course / all / exercise`；考试 `scope=exercise` 单独使用 `course + exercise_id`，不接收 `homework_id / game`，须在课程详情的在线考试页明确安排。课程与一键全部作业不自动纳入考试。技术用 `generate_only` 与 `selftest` 保留在 Go CLI，不可从普通服务 API 冒充完成状态。缺 scope 且带作业 ID 的旧 submit 请求统一扩展为整份作业。旧版缺 scope 的 submit+game 请求会归一化为整份作业，避免旧浏览器继续只做一关。

考试状态区分答案保存、已交卷、成绩已公布；已交卷不等同满分。教师禁止交卷后读卷时，仍能通过本人答卷摘要和考试概要显示已交卷；摘要不臆造逐题保存计数。需要原站入场、教师解锁或监考浏览器的考试，目录提供原站入口，后台遵循平台状态。接口、支持题型、保存回读与交卷证据详见 [在线考试协议](exercise-protocol.md)。

课程执行会重新读取账号活动课堂并核实所选课堂归属，读取完整作业列表再开始动作。已完成的判定来自完整、唯一的必做关卡分数清单与精确满分，不采用汇总完成数。上游明确标记为选做的关卡不执行，也不计入待完成清单、进度分母与最终满分核验；整份作业只有选做关卡时从本次作业计划中排除。零分值本身不能代替选做标记。单份作业中的必做关卡仍顺序执行。失败或平台写入结果未知的作业保留给服务人员，其他独立作业继续执行；不自动重放未知写入。

普通用户收到专门投影后的服务摘要，不返回模型次数、成本、预算、内部错误码、原始 events、模型原文或上游响应。需要管理员处理的状态不能被当作已通过；用户无需自行调模型或判断自测错误。具体执行机制见 [async-jobs.md](async-jobs.md)。

课程卡片的作业数是上游课堂作业总数，不代表待完成关卡数。只有打开一门课堂的作业详情时，服务才读取最多 100 份作业的关卡进度，最多 4 个并发读取，并设 12 秒总时限。完整且唯一的进度清单核验成功后返回 `requiredProgressKnown=true`、`requiredChallengeCount`、`finishedRequiredChallengeCount`；必做分母不含选做，全为选做的作业从详情列表排除。进度缺失、不完整、读取失败或超时不会回退到原始总关数猜测完成率，用户看到“安排时核验必做进度”。原始 `challengeCount` / `finishedChallengeCount` 字段仅为兼容保留，不作为必做完成判断。

## 课程信息、详情预取与每日服务统计

课程列表在自身课堂清单返回后，最多 4 并发、3 秒总预算读取已观察的 `top_banner.json`。教师使用名单 `teacher.real_name` 或详情 `teacher_name`；学生人数仅使用 `student_count`。上游 `members_count` 包含教师，不能直接显示成学生人数。元数据在同一认证客户端内成功缓存 5 分钟，失败不阻断课程清单，缺失字段明确待同步，真实 0 保留。任务执行期间遍历 `Courses` 不附带这些额外详情读取。

浏览器取得课堂清单后，在当前会话内渐进预取每门课程的作业与考试列表，后台最多 2 个读取，总读取并发最多 3 个，为点击请求保留优先处理能力；相同目标的请求合并。缓存默认保鲜 2 分钟，打开详情先显示已有结果，过期时再验证；右上角 SVG 刷新按钮强制更新该课程的作业与考试两份列表。刷新失败保留上次可用结果并给出固定文案，空列表正常缓存；切换 tab、关闭弹窗或切换账号后的旧响应不会覆盖当前页面。缓存仅在浏览器内存，退出立即清空队列和数据，已发送的只读请求即使稍后完成也会被丢弃；不写浏览器持久存储，不执行进入实训、保存、评测或交卷。

`GET /api/service/today-summary` 的字段为 `date`、`timezone=Asia/Shanghai`、`completed_students`、`completed_questions`。以正式核验证据的时间划定北京时间自然日，仅统计已核验平台身份对应的 submit run 完成结果；平台 owner 白名单读取没有 100/500 条分页截断。客观题按目标关卡内单题位置计数，编程关卡计 1 题，按用户和目标去重。题库历史采集、已通过/选做跳过、生成、自测、部分分、未确认和仅交卷未判分考试都不计；缺少可靠 run 或核验绑定的历史记录保守排除。没有将近期任务数或题库总量冒充今日完成量。

每日汇总缓存 60 秒，跨北京时间午夜立即失效，每次请求仍核验会话与当前账号状态，查询预算 3 秒；不可用返回 503，前端不编造为零或展示昨日数字。对外只返回日期和计数，不返回身份、题干、答案或费用。页脚在短页面落到底部，在长页面跟随内容之后，顶栏和侧栏不再展示“已连接”提示。

## 题库概况

用户端左侧栏底部、移动端主内容下方展示题库汇总及服务说明，课程页和完成进度页均保留入口。点击《用户准则》沿用登录页弹窗，关闭后焦点返回对应入口。该区域没有题干、答案、代码、个人任务、模型费用或额度，也不将总量当作课程覆盖率或成绩承诺。

`GET /api/question-bank/summary` 复用当前会话、账号状态与同源校验，只返回 `verified_objective_questions`、`verified_programming_problems`、`total_verified_questions` 三个非负整数。客观题仅统计资源证据完整且存在已核验答案的独立 `question_key`；编程题统计当前仍符合正式完整通过、保存/提交哈希绑定条件的独立 `revision_hash`，同题多候选或执行契约不重复。历史整份客观题批次快照不直接换算成单题数。合计严格等于两项之和。

服务端使用一次只读聚合查询，最多缓存 60 秒；缓存命中也重新核验当前账号。查询预算 3 秒，未配置或读取失败返回 503；真实空库才返回 0。浏览器会话内一分钟最多自动读取一次，并提供手动刷新入口；失败显示“题库概况暂未同步”，不把错误伪装为零。退出账号会清空概况并丢弃过期响应。

## 管理员与管理 API

管理员需要使用同一个头歌登录流程。仅经过核验的头歌数字 ID 可通过 `PLATFORM_ADMIN_USER_IDS` 引导为管理员；头歌教师身份、姓名、客户端字段和页面导航都不授予管理权。普通用户访问管理 API 返回 403，未登录返回 401。

首次引导时，使用本人头歌账号登录，从 `/api/auth/me` 的 `data.user.id` 核对真实数字 ID。把经核验的 ID 填入服务器环境，再重启并重新登录。多个数字 ID 用逗号分隔，不能填写手机号、登录名或平台随机用户 ID。

```dotenv
PLATFORM_ADMIN_USER_IDS=VERIFIED_NUMERIC_USER_ID
```

这里的 `VERIFIED_NUMERIC_USER_ID` 是说明占位，部署时必须替换为实际正整数，或者留空；原样使用会导致配置校验失败。环境列表会在登录时提升并持久化管理员角色，移除环境列表中的 ID 不会自动降低既有角色。当前没有通过 HTTP 任意授予/降低管理员角色的接口；如需立即收回访问，可由另一管理员禁用该账号。

| 方法 | 路径 | 数据或操作 |
| --- | --- | --- |
| GET | `/api/admin/overview` | 用户、运行容量、模型配置与台账汇总 |
| GET | `/api/admin/usage` | 同源使用台账汇总，非用户账单 |
| GET | `/api/admin/users` | 近期用户列表，`data.items`，固定上限 100 |
| POST | `/api/admin/users/:id/status` | `{ "status": "active" }` 或 `disabled`，`:id` 为平台用户 ID |
| GET | `/api/admin/jobs` | 近期跨用户任务与原始受控诊断，上限 100 |
| GET | `/api/admin/jobs/:id` | 单任务详细内部记录 |
| POST | `/api/admin/jobs/:id/cancel` | 按管理员权限请求取消，并写审计 |
| GET | `/api/admin/audit` | 最近管理及登录审计，上限 100 |

禁用账号会删除该用户当前内存会话，并请求停止其排队和运行任务。重新启用不恢复旧会话或重放已停止任务，用户需重新登录。管理员不能通过账号状态接口禁用自己；没有独立的跨设备会话管理 HTTP 接口。

管理用量来自 `questionbank.sqlite` 的实际 `usage_ledger` 全表汇总，不是把近期 100 条任务费用加起来。字段包括 `model_calls`、`input_tokens`、`cached_input_tokens`、`output_tokens`、`cost_micro_usd` 、`reserved_micro_usd`、`settled_cost_micro_usd` 和 `unknown_calls`。金额单位为百万分之一美元；`cost_micro_usd` 是台账记录值（含未知计费时的估算），`settled_cost_micro_usd` 只汇总已确认计费，`reserved_micro_usd` 只汇总非 settled 记录的预留，`unknown_calls` 是待核对次数。不要将预留与记录成本重复相加。它不是供应商实时余额、发票、用户应付账单或周期额度。

任务详细结果可能包含模型失败原因、自测状态、评测阶段和逐关进度；管理员也不获得用户密码、上游 Cookie、模型密钥或完整模型响应。诊断不提供通用上游请求代理能力。

## 用户准则与已下架功能

登录页底部提供可点击的《用户准则》及做题数据收集提示。弹窗文案由 `web/src/guidelines.ts` 维护，说明授权账号使用、上游与模型结果边界、题目/作答/代码和评测状态的收集与复用、必要内容发送给模型服务，以及服务维护和反馈。登录后会扫描已通过的任务，只有满足证据门槛的答案进入已验证题库；详见 [已通过答案采集](verified-collection.md)。这次更新增加了清晰告知，没有扩大采集权限或取消账号隔离。阅读弹窗不发起登录、采集或任务请求，关闭后继续保留表单中尚未提交的输入；输入不插入 HTML、不进入持久化浏览器存储。

卡密功能已完全下架。浏览器无卡密输入、管理页或卡密 API 调用；后端不再提供签发、兑换、撤销、列表和资格校验。旧 `/api/auth/config` 及管理员卡密路径返回 404；登录携带旧 `access_code` 字段按未知字段返回 400，刷新新版页面后只发送账号密码。旧 `ACCESS_CARD_REQUIRED` 环境变量不再读取，Compose 和示例配置已移除。新平台数据库不创建卡密表，历史数据库原有卡密表及审计记录保留但不再参与服务准入。

## 当前安全措施与边界

- 平台身份必须来自服务端成功认证的数字 ID，任务数据按平台 owner 隔离，管理接口验证当前角色。
- 登录后轮换站内会话；Cookie 为 HttpOnly、SameSite=Lax，线上 HTTPS 配置 Secure。
- API 校验 Origin 与同源 Host，或精确 `WEB_ORIGIN`；不使用带凭据的通配 CORS。
- 登录按账号与 TCP 来源地址做进程内窗口限速；来源使用 RemoteAddr，不盲目信任客户端传入的转发 IP。经代理时来源地址可能共享。
- 请求体和标识有上限，作业清单与任务目标先核验；有界队列、并发、费用与时间边界避免无限执行。
- 禁用、管理员停止任务与成功登录写入审计；审计不记录密码、认证头或 Cookie。
- 上游 CookieJar、会话、登录限速窗口和执行闭包在内存；数据库与日志不应放在公开静态目录或 Git 中。

这些是当前实现的应用边界，不等于分布式隔离、完整渗透测试或正式安全认证。当前没有自动支付、退款、套餐计费、周期额度、MFA、跨节点会话或分布式 worker。

## 持久化、升级与运维

应用数据目录包含 `platform.sqlite`、`jobs.sqlite`、`questionbank.sqlite` 及 SQLite 运行时可能存在的 WAL/SHM。容器统一放在 `/data` 持久卷，平台数据库以仅属主读写权限创建。备份应停止应用后冷备整个数据卷，或使用 SQLite 一致性备份机制；运行中只复制主文件可能丢失 WAL 数据。

单机服务重启后个人身份、任务历史与审计保留；内存站内会话与上游客户端丢失，所有用户重新登录。任务记录会改为中断或待核验，不会自动重建客户端并继续上游写入。关闭浏览器或普通退出登录不会自动撤销已接收任务；显式取消和禁用账号才请求停止相应执行。

升级前备份整个数据卷并保留前一镜像。回滚源码不能恢复内存会话，不能撤销已发生的头歌提交，也不自动倒退数据库；如需恢复数据，应使用同一一致性检查点的完整备份，不能只恢复 platform 库而让任务 owner 对应关系丢失。

部署继续使用本机 `ssh main`、Docker、11454 与用户管理的 1Panel 反代。发布与健康检查步骤见 [部署说明](../deploy/README.md)。

后台执行独立于浏览器会话，每 2 秒检查持久化用户状态；退出浏览器后仍继续此检查。账号禁用或授权撤销会协作停止后续动作，已发送的上游提交仍需核验实际结果。内部题库采集繁忙时跳过本次采集，避免占住答题 worker 等待。


截止状态：用户端作业列表只展示仍可安排的作业。服务端优先使用头歌返回的 `已截止 / 已结束 / closed / ended` 状态，并按 `end_time / deadline / end_date` 的上海时间兜底判断；缺少日期不当作截止。补交作业只有在上游明确给出有效延长截止时间时才保留。`course` / `all` 任务在规划和每份作业开始前都会复核截止状态，已截止作业不会进入运行实例、模型调用或提交；执行中跨过截止时间时停止后续关卡。历史题库采集仍读取原始列表，以保留已完成作业的核验记录。


管理端任务列表按用户、课程、作业与当前关卡、状态及带单位的进度、具体原因分别展示。姓名通过平台身份在服务端关联，不依赖前端最近100位用户列表；课程与作业名称来自已验证的上游列表及历史执行结果，并保存在仅用于显示的目录中。历史账号缺乏身份关联时明确标记“历史账号未关联”，不按登录名哈希认领。原始任务标识、原因码与诊断放在默认折叠的技术记录中；普通用户任务接口不增加这些管理信息。

作业和关卡必须属于同一目标。课程或全部课堂任务的列表优先展示需要跟进的作业及其自身失败关卡；如果该作业在读取清单前已停止，则显示“尚未进入关卡”，不借用整批任务最后处理的另一份作业关卡。服务端管理 `context` 中空的 `level` 是已确定的展示结果，前端不再拿全局 progress 补成别的作业。旧记录缺少 context 时，也只有 course/homework 标识匹配后才能使用进度作为关卡补充。

一批任务中有多份作业需要跟进时，主列表显示简短数量，详细记录逐份列出课程、作业、具体原因与受控诊断。清单无法唯一定位、自测未通过、保存源码与候选不一致、运行时限结束等原因分别显示，不统称为“提交待确认”；源码不一致仅说明比对未通过，不据此推断用户修改了代码。已通过的作业仍计为完成，其余未开始的作业不计为失败关卡。

新任务持久化整批结束原因 `stop_reason=time_limit` 或 `canceled`，管理摘要再通过 `pending_homeworks` 显示尚未开始的作业数量。没有类型化结束原因的历史记录，仅在整批记录为取消、最后执行作业为中断且该作业诊断明确记录 deadline 时，标记 `deadline_observed`，显示“最后执行的作业记录了超时，整批已停止”；不会仅凭任意较早的子任务超时就断言整批达到时限。逐份作业的具体失败原因与批次结束信息同时保留，避免把前面已失败的作业都解释成最后一次超时。

内部题库采集与答题任务分开解释。新增 0 条但有重复条目表示已核验内容在题库中已有；跳过原因按作业、关卡或结束事件注明单位，未确认是跳过的子集。正常达到单次采集上限而无读取失败的记录显示“本次分批采集已结束”，不作为人工处理告警；历史原始失败记录保持不变。判定不明确的失败仍进入跟进列表。概览“需人工处理”数量按当前答题任务中实际需跟进的记录计算，不包含题库采集或已被后续安排替代的历史失败，不代表数据库全部历史异常总数。计数规则与原因解释见 [已通过答案采集](verified-collection.md)。

任务运营默认显示“当前任务 / 答题服务”。排队、运行中的记录全部保留；同用户、模式、请求范围、课程、作业和关卡目标相同的已结束记录只保留最新一次，先前记录归入“历史记录”。归并使用原始请求身份，不使用详情中高亮的失败作业。未关联历史账号的已结束记录也归入历史。历史只改变展示位置，仍可查看当次结果、费用与具体原因；没有删除任务或审计。题库采集有独立筛选入口。当前和历史均基于服务器返回的最近最多 100 条记录，不宣称覆盖全量历史。
