# 当前架构与迁移决定

当前唯一 Web 服务为 `cmd/web`，同时托管暖纸珊瑚主题的用户端、管理端和应用 API。浏览器 TypeScript 编译为 ES modules；Go 维护全部协议、身份、执行、AI 与题库逻辑。

客观题的正式满分答卷保存在整关快照题库；登录采集另行建立按单题检索的已验证答案库。两者不是同一张表，服务显示已完成也不表示全部历史单题都已采集。求解含图片的客观题时，先读取当前图片内容，构造内容哈希快照，再通过 `FindObjectiveVerifiedWithResources` 核对图片字节、题目/选项归属及 SHA256 占位引用。完全相同的快照可以复用已有正式满分答卷，后续仍须在当前账号提交并复核分值；较新的未满分候选不会覆盖满分候选。原始图片 URL、缺失图片或内容变化不能沿用旧图证据。

## 身份与租户边界

`internal/platform` 只接受上游成功登录后返回的正整数用户 ID 建档。平台用户 ID 和个人 `tenant_id` 由服务端生成，登录名与姓名可变；没有单独注册和本站密码。每个个人账号对应一个数据分区，当前没有组织成员、共享课堂或跨租户协作功能。

会话保存平台身份与独立的 Go 协议客户端。每个 API 请求重新核对平台用户状态、角色和准入权限。任务 owner 由已验证平台身份产生，再由任务存储内部哈希处理；客户端不能指定 owner、租户或管理员身份。旧登录名 hash 的任务不自动迁移或归属。

角色分为 `user` 与 `admin`。`PLATFORM_ADMIN_USER_IDS` 用经核验的头歌数字 ID 引导管理员，教师身份不授予平台管理权。准入由已核验身份、角色与账号状态决定；卡密能力已下架。支付、套餐和周期额度不在当前实现中。

## 进程内异步执行

```text
web/src → internal/web
          ├─ internal/platform → platform.sqlite
          ├─ internal/jobs → jobs.sqlite
          └─ internal/taskservice
               ├─ RunCourses：单课堂或全部活动课堂的作业编排
               ├─ RunHomework：选中作业全部关卡
               ├─ internal/solver / answer / questionbank
               └─ internal/educoder → Educoder API
```

HTTP 接口立即返回任务标识，有界 worker 在同一个 Go 进程里执行，不运行 CLI 子进程。全站并发、单账号并发和模型并发独立配置。相同目标保持幂等；`all`、`course`、`homework` 的包含关系在调度时避免同账号重叠执行，最内层运行实例和 game 写入另有目标锁。

用户可停止运行中的作业安排，并在确认失败、停止或中断后重新执行。`POST /api/jobs/:id/retry` 根据当前登录身份读取原记录，保留原安排范围，交由现有 worker 使用当前会话客户端重新读取上游进度，只处理未完成的必做内容。服务器按原任务生成持久幂等键，防止重复点击或多页面重复安排；原记录保留为历史。考试、采集、已完成及包含未确认提交结果的记录不开放此操作。

单作业内按顺序校验并执行关卡，遇到不确定结果时停止继续写入该作业；课程任务记录需要服务人员处理的作业，并继续其他独立作业。状态投影分为用户摘要与管理员诊断。模型成本、自测反馈和内部原因不透传到普通用户端。

上游密码、Cookie、运行密钥和模型密钥不写入任务记录；数据库保留必要身份、幂等键、进度、授权题库证据、反馈工单、审计和费用台账。工单正文仅用于用户与管理员沟通，不进入题库或模型请求，审计不含正文。任务重启恢复只修正状态，不恢复内存闭包或自动重放写入。

已通过题目采集使用独立于答题 worker 的有界执行通道，默认完整遍历，不受答题 `JOB_TIMEOUT` 或旧版三分钟/数量/累计流量限额截断。采集仍可取消，服务关闭或权限撤销会终止读取；单次 HTTP 请求及响应大小仍受限。新的已认证登录会重新安排已结束的扫描，进行中同账号扫描去重；当前没有脱离登录凭据自动恢复的持久执行闭包，已入库的验证结果保留。

## Go 模块边界

- `internal/web`：应用 API、用户与管理员 DTO、会话、来源校验和静态托管。
- `internal/platform`：平台身份、角色、权限隔离的反馈工单及安全审计。
- `internal/jobs`：持久任务记录、队列、有界并发、幂等与取消。
- `internal/taskservice`：课程、作业及单关应用编排；只读已通过答案采集。
- `internal/educoder`：唯一协议客户端，处理登录、课堂、作业、题目、保存、提交与结果查询。
- `internal/solver`、`answer`、`problem`、`questionbank`：代码求解、客观题模型调用、快照指纹、候选与验证证据、使用台账。
- `internal/avatar`：固定官方来源头像读取与内存缓存。

客观题使用独立候选和验证表，图片以真实字节参与模型输入，以内容哈希绑定题库；不会把客观题答案保存进编程源码表。CLI 作为维护工具复用这些 Go 模块，不是 Web 的执行入口。

## 已移除与当前未实现

已从当前源码和镜像移除 `typescript/` 协议库、HAR 重放工具、`resource-reuse/` 编译 UI 与图片、`cmd/reuse`、`internal/compat` 和旧网关方案。Git 历史与旧发布目录保留恢复能力。

当前是单实例、单机 SQLite 和内存会话。没有跨节点调度、共享会话、组织级租户、支付结算、付费套餐、周期额度或自动化客服修复承诺。管理员能检查内部诊断、处理账号和任务；任何结果未知的上游提交仍须先核验，不能以“服务人员处理”代替实际已通过状态。

## 部署

多阶段镜像只在构建阶段使用 Node.js，运行时是 Go 与静态页面。应用监听 11454，数据在 `/data` 持久卷，模型密钥以 Docker secret 挂载。`ssh main` 管理部署，用户自行维护 1Panel 反代。详细配置见 [平台与运维](PLATFORM.md) 和 [部署说明](../deploy/README.md)。

## 浏览器详情缓存与只读展示汇总

`web/src/course-cache.ts` 只维护当前登录会话的作业/考试 GET 结果，拥有请求合并、后台预取、点击优先、两分钟保鲜和换会话丢弃能力。浏览器仍不运行协议客户端、CLI 或答题逻辑；右上角详情刷新只重新读取两份列表。课程教师与学生数由 Go 读取列表和只读课程 banner 后投影，人数未知不以成员总量代替。

用户侧栏的题库量与服务完成量使用两个不同的只读汇总：前者按客观题、编程题、绘图题统计库存（包含尚未验证的候选，不能直接视为可信答案），后者在同一数据库快照内同时计算累计与北京时间当日的可核验完成量。累计学生按全历史平台 owner 去重，题数按学生与目标单题去重，不将每天的学生数相加；采集、跳过和缺少可靠完成证据的历史不计入。两种汇总均需要有效平台会话、仅输出计数；全站计数按分钟缓存，内部查询失败不会伪造为零。题库响应另带按当前会话独立查询的 `contributed_questions`，通过已验证的 owner 归因按语义题去重，未绑定身份的历史采集保守排除；该个人字段不进入全站缓存。重复登录后的客观题采集以幂等收据补充归因，编程题复用现有正式执行与文件哈希证据。

## 只读元数据容错

课程列表、作业列表、作业头信息、运行实例关卡清单和成绩读取共享有限重试。只有超时、连接中断、429 和 5xx 才重试，包含首次请求最多三次，等待 200/400 毫秒；取消、认证、响应超限及结构错误立即结束。错误仅保留固定操作名、阶段、类别、状态码和次数，不保留账号、签名查询或上游正文。缺失、null 以及总数尚未满足的重复分页保持未知，不当作没有作业或已完成。

重试按明确的只读操作开放，不根据 GET 方法全局重试；会创建运行环境的 `shixun_exec.json` 和保存、提交链路沿用原有边界。采集客户端已有三次传输重试，外层不再叠加，避免放大为九次。

## 反馈工单

`internal/platform/tickets.go` 维护工单、消息和状态，使用现有单连接 SQLite 事务及唯一键保证并发幂等、频率和数量上限；`internal/web/tickets.go` 提供本人及管理员两个同源应用命名空间。身份、状态和管理员角色在事务内复核，分页游标不能改变 owner 范围。工单表在现有平台数据库上增量创建，不依赖任务 worker 或 CLI 子进程；正文只经对应权限的 API 返回，不写入审计详情、题库或求解器。接口、状态、限量及留存语义见 [平台与运维](PLATFORM.md)。


## 独立 Linux 终端

只有 `code_editor` 为空、唯一环境为 `tab_type=4` 的代码关卡进入终端链路。混合代码编辑器与终端的普通编程题保持原流程。Go 适配器通过 `start.json` 与独立 WebSocket `/ws` 执行一次脚本，以随机边界、远端脚本哈希和退出码确认结果；未知结果不重放。终端候选使用独立的 `terminal` 执行契约，脚本执行成功后仍须正式评测和当前关卡满分复核。终端占位编辑器文件不充当答案或源代码证据；当前工作区通过与可独立复用的答案分别记录，前者不会晋升为全局可信答案。细节见 [terminal-protocol.md](terminal-protocol.md)。


## 模型临时故障退避

编程、客观题和现有考试模型重试只对可用性故障使用可取消的随机退避，连续等待范围为0.5–1、1–2、2–4、4–8秒；合法Retry-After秒数或HTTP日期转换为最多60秒的数值提示。每次已派发请求先保存用量和检查点，下次估价和预算检查通过后才等待、再派发。真实输出错误、鉴权和不明的成功响应中断不进入这套退避。编程连续故障状态跨显式续跑保留，其他流程保存在原私有检查点中；全站并发、调用和费用上限以及未知预留均保留。


## 管理员接续任务

管理员通过服务端显式can_retry能力重新执行确定可重试的作业任务，使用目标用户当前有效的登录客户端，并与用户端共享retry-job幂等键。请求只接受空对象，保留原任务范围、选做过滤与已通过跳过行为，执行前再次检查用户权限和登录有效期。缺少用户登录时需该用户先恢复登录；结果未知的提交仍走复核入口，不能直接重试。界面在请求及刷新期间锁定同一任务的重试、复核、停止操作，确认框标明学生、课程和作业；管理操作记录审计，不将管理员客户端用于学生任务。
