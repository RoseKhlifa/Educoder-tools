# 异步课程执行服务

Web 请求只负责校验会话、入队和返回任务 ID。`cmd/web` 启动 `internal/jobs.Manager`，在同一个 Go 进程中运行有界 worker。浏览器不会启动 `cmd/educoder`，服务也不会用 `os/exec` 调 CLI。

当前用户界面面向服务交付：选择课堂或一键处理全部未完成作业，然后查看进度。创建任务使用 `POST /api/jobs`，响应是 `202` 与 `data.id`。客户端通过 `GET /api/jobs/:id` 查询，也可读取 `GET /api/jobs` 恢复自己的历史；`POST /api/jobs/:id/cancel` 请求停止后续执行，不能撤销已经到达上游的保存、提交或评测。

## 用户停止与重新执行

当前安排的卡片和详情按服务端返回的 `can_cancel / can_retry` 展示操作。仍在排队或运行的作业可以请求“停止任务”；页面继续查询原任务，只有后台确认结束后才展示可用的“重新执行”。停止请求成功不代表执行已经停止，也不会同时创建第二个执行实例。

本人失败、取消或服务重启中断的 `submit` 作业支持 `POST /api/jobs/:id/retry`，请求体为空或 `{}`，返回 `202` 与新的任务标识。范围仅限 `homework / course / all`，服务端从原记录复制范围，使用当前登录会话的上游客户端重新核验并执行；客户端不指定 owner、目标、模式或重试键。每个原任务对应一个确定的、按用户隔离的重试键，重复点击、网络响应丢失或旧页面重放都会取得同一个后续任务，即使它已经结束。后续任务再次失败时，从这条新记录继续重试。已通过的必做关卡和作业会先查询精确满分证据再跳过。

已完成、仍在执行、考试、内部采集及上游写入结果未知的记录不开放这条重新执行接口。平台仍需核对的记录保留反馈与管理处理流程。历史记录只展示当次结果，不提供新的执行按钮；新安排替代同一范围的旧记录后，旧失败进入折叠历史。允许重试的失败记录不再永久锁住课程选择和一键安排。

运行记录进入终态后，浏览器重新读取其对应课程的作业明细（`all` 则更新当前课程列表），使“未完成作业”数量、课程状态和打开的详情同步变化。若先前预取仍在进行，作业强制刷新会等待它结束后追加一次新读取；重复刷新合并，退出账号会使旧会话的刷新链失效。任务结果不直接篡改上游作业完成证据。

## 课堂与账号执行范围

```json
{"scope":"course","mode":"submit","course":"COURSE","idempotency_key":"CLIENT_GENERATED_KEY"}
```

```json
{"scope":"all","mode":"submit","idempotency_key":"ANOTHER_CLIENT_GENERATED_KEY"}
```

`course` 范围要求课堂标识，不接受 `homework_id` 或 `game`；`all` 范围不接受任何课堂、作业或 game 参数。后端从当前会话客户端读取活动课堂，并确认所选课堂归属。先解析完整清单，限制在 20 个课堂与 100 份作业内，再开始执行。

每份作业先读取完整且唯一的目标关卡得分；明确必做关卡数且全部精确满分才计为已完成并跳过，`finished_challenge_count`、`passed_count`、已提交标记不能代替逐关得分证据。上游明确标记为选做的关卡从执行计划、待完成数量、进度分母及最终核验中排除，不能仅根据 `challenge_score=0` 判为选做。全为选做的作业不计入 `total_homeworks`。剩余作业调用现有 `RunHomework`。某份作业失败或结果未知时记录 `needs_service` 并继续处理其他独立作业；仅有真实正式写入未知的关卡会被隔离，不能重放该关卡，其他关卡仍可执行。

课程任务结果保留 `total_homeworks`、`completed_homeworks`、`skipped_homeworks`、`needs_service_homeworks` 和每份作业结果；completed 包含已完成而跳过的作业。管理员读取详细结果，普通用户只接收服务状态与进度摘要。整批最多 30 分钟，模型实际费用和未知预留共受 $2 内部预算约束；每份作业的 $0.50 上限仍保留，预算不是用户余额或计费套餐。

## 整份作业与单关维护模式

答题提交默认使用整份作业范围：`scope=homework`、`mode=submit`，请求不携带 `game`。服务先读取并严格校验这份作业的完整关卡清单，再按位置顺序处理必做关卡；选做关卡不进入题目求解、不调用模型、不保存或提交答案，也不列为失败或待处理。已经由当前作业进度精确证明满分的必做关卡会标记为 `skipped`。每个新提交后都会重新读取对应关卡进度，只有精确满分才进入下一关。结束前还会对全部计划必做关卡做一次最终满分核验，只有 `completed_levels == total_levels` 且 `failed_levels == 0` 才报告 `passed`。真实正式提交未知、预算耗尽、取消或清单不完整会停止相关执行；图形环境配额、资源不可用及保存未提交等明确写入前失败会隔离并在其他关卡完成后有界重试。

为兼容已经打开的旧版浏览器页面，服务端也会把缺少 `scope`、但同时携带 `game` 的旧版 `mode=submit` 请求归一化为整份作业任务，并清除单关 `game` 字段；这类请求不会再退化为只执行一关。

作业可能只选择底层实训的一部分关卡；roster 读取以作业进度和 `challenge_count` 的交集为准，底层实训 header 中未被该作业选中的关卡不会阻塞批处理。客观题模型请求为答案 JSON 预留最多 8192 个输出 token，避免推理文本占满默认上限后把后续关卡误置为待复核。

编程题每关默认最多 3 次模型调用和 3 次评测；客观题每关最多 3 次模型调用、15 次正式候选提交。已确认的自测失败或未满分会把反馈交给模型修复。编程题一次任务耗尽本轮预算后不会在服务端自动追加轮次；用户或管理员可在结果明确可重试时显式创建新的幂等重试任务，已确认通过的关卡会先跳过。每次运行保留失败源码哈希、样例反馈、历史候选、累计费用和未知计费预留；已确认失败的相同源码不再次保存、自测或正式提交，模型会收到有界修复历史；当前编辑器代码不被当作不可修改的正确模板。正式提交结果未知、源码并发冲突、费用预算耗尽或作业截止时保持真实状态，不将其改写为通过。

模型输出截断或 JSON 无效会在剩余次数、费用和时间预算内自动重新生成；截断后的请求关闭可选推理并使用 8192 输出 token，防止反复占满额度。未知计费预留仍计入整份作业预算。自测比较规范 CRLF/LF，并忽略一次终止换行；内部空格、换行和答案内容仍须相同。仅被旧换行规则误拒绝的候选可重新完整自测，再进行正式评测，不直接标记通过。

批处理保留子运行的真实状态，`selftest_failed`、`attempts_exhausted`、`model_error` 不再统称为平台待复核。模型供应商返回 HTTP 402 时使用稳定的 `model_provider_payment_required` 原因码，表示供应商账户余额或额度门槛；该状态不进入瞬时故障重试，也不等同于平台自己的 `budget_exhausted`。管理员结果每关包含 `reason_code`、`model_calls`、`max_model_calls`，用于排查停止位置和尝试次数。普通用户接口使用专门 DTO，展示处理进度和服务状态，不返回内部原因、模型调用次数、费用或原始事件；这些与早期调试工作台的公开结果不同。模型原始响应和自测原始内容不作为用户内容。保存、执行流或正式提交结果未知时仍停止自动写入，避免重复操作。

代码自测帧解码失败与正式提交未知使用不同原因。自测仅进行 `evaluate=0` 保存和运行流；当 `self_test_status=unknown` 且还没有正式 `evaluation` 时，原因码为 `selftest_stream_unconfirmed`，明确的 WebSocket 连接失败仍用 `selftest_connection_failed`。已有正式 `evaluation` 的未知结果保持 `submission_uncertain`，残留的自测消息不会把它误标成自测故障。两种情况都保留未核验状态，而不是把协议异常当成错误答案交给模型反复生成。批处理同时保留失败子任务实际提供的非空诊断，过滤空白并去重；不会再用 nil error 生成 `diagnostics:[""]` 而丢失子任务原因。

代码题未开放查看测试输入/输出时仍可正式评测。适配器只跳过输入和预期输出同时为空字符串的公开占位样例；没有公开样例时，`submit` 模式继续正式提交，`selftest` 模式返回 `selftest_skipped`。自测流支持标准及 URL-safe Base64、可选 padding 和 ASCII 空白，仍要求编码后的精确结束标记，不以任意明文兜底。正式轮询收到 `status=0` 时，只有明确失败结果（正的错误数、测试结果为 false 或编译失败标记）才进入已结束未通过的修复流程；裸状态码和缺失证据仍需只读核验，不重新提交。完整协议条件与原始 HAR、线上流核验和本地合成测试的证据区别见 [代码题协议说明](programming-protocol.md)。

Web 客观题执行会在生成前读取题干和选项中的真实图片，按题号、选项绑定给模型，不会要求模型仅凭图片地址猜题。图片仅在内存中处理；原地址（含签名查询）在持久化快照和模型文本中替换为内容 SHA-256 标记。下载限制为同源附件端点及已验证的官方图片存储重定向，不向图片存储转发账号认证；图片缺失、格式不支持或超限时，管理员诊断保留资源读取原因，用户看到服务处理中；不会提交信息不全的答案。

客观题先尝试当前快照的已验证题库答案，再尝试按实验、关卡、题数、题型和选项形状精确匹配的外部候选；外部候选只是首次未验证提交，平台判分后才可能晋升。模型最多生成一次带有每题候选排序和置信度的答案；当平台只返回总分时，系统保持其他答案不变、一次只替换一道题，并在已知且可比较的分数上升、下降或不变后锁定、恢复或排除该候选。分数未知、最大分变化、提交结果未知或题目快照变化都会立即停止，绝不重放未知写入。每关提交次数仍受独立绝对上限约束，已确认的逐题结果优先于总分反馈；跨运行只复用完整上下文指纹下的已证明答案。

仅生成答案或公开样例自测使用 `scope=current` 并携带 `game`，只处理当前关卡，不会继续同一作业的其他关卡。

默认配置为 16 个 worker、256 项队列、单账号 16 项待处理、单账号最多 4 个并行执行、模型并发 8、单任务 30 分钟。账号内同一目标仍只保留一个排队或运行任务；同一账号的不重叠作业可以并行，不同账号也可以并行。课程任务与该课堂的作业任务互斥，全部课堂任务与该账号的其他执行目标互斥；它们是不同请求，不会错误合并为相同幂等响应。模型并发是进程内同时发起的模型请求上限，实际供应商 RPM 仍由模型服务商账户限制。HTTP 请求取消只取消等待，不会取消已接受的后台任务。

任务状态、幂等键和公开进度保存在独立 SQLite 中。服务重启时将未完成任务标为 `interrupted` 或 `uncertain`，不会自动重放可能有副作用的保存或提交请求。owner 由服务端平台身份产生，再由任务存储哈希；旧登录名 hash 不会自动归属到新身份。Cookie、密码、模型密钥、`sec_key`、WebSocket 地址和模型原始响应不写入任务数据库。

模型密钥通过 `DEEPSEEK_API_KEY_FILE` 指定的 Docker secret 读取。空密钥时服务仍启动，浏览、课堂和任务功能可用；管理员容量中的 `model_configured` 为 `false`，创建普通作业执行任务收到统一的 `503 SERVICE_UNAVAILABLE` 服务提示。考试列表及已交卷摘要核对不需要模型，仍可使用；尚未提交的考试执行到需要生成答案时保留 `needs_provider`，不保存或提交答案。配置密钥后重启容器即可启用模型执行。

CLI 仍用于手动验证和运维调试，Web 任务不会为每次答题创建 CLI 进程。任务服务直接复用同一 Go 协议客户端、solver、objective taskservice 和题库连接，在 goroutine 中执行，并把状态写入可恢复任务记录。

## 在线考试范围

在线考试使用独立范围，不混入课堂实训作业或全部未完成作业批次：

```json
{"scope":"exercise","mode":"submit","course":"COURSE","exercise_id":501,"idempotency_key":"EXAM_REQUEST_001"}
```

浏览器通过 `GET /api/courses/COURSE/exercises` 读取考试元数据，使用同一 `POST /api/jobs` 与本人任务查询接口。服务在现有 worker 中直接调用 `RunExercise`，共享模型并发与费用账本。同账号同一考试不会并发覆盖答案；不同考试与实训作业的目标保持独立。幂等键按 owner 隔离，旧键重放不重新生成、保存或交卷。

服务先查本人交卷摘要。已交卷时只读摘要和 `common_header`，教师禁看完整试卷也能展示已交卷与公开成绩，不依赖模型。历史摘要的题目总数不等于本次已核验保存数，不能据此把全部题目计成已答。新执行在入场、监考、个人剩余时间和身份检查通过后，先生成并校验全卷，再逐题保存、回读，最后检查未答数并交卷一次；未知保存/交卷结果停止自动写入，仅做只读核对。已交卷、成绩待公布、已评分和精确满分分别表示，不保证提交即满分。

当前支持单选、判断和单空文本，缺少媒体内容或未知题型在写入前停止。单空回读结构由当前公开学生答题组件源码确认，实际保存仍必须重新读取服务端 `user_answer` 并逐字匹配；HAR 保存 ACK 本身不算回读证据。需要教师解锁、原站监考或专用客户端的考试保留原站流程。详情、字段及证据来源见 [在线考试协议](exercise-protocol.md)。


## 管理排障与恢复

普通用户不负责解读协议或模型报错。管理员通过 `/api/admin/jobs` 和 `/api/admin/jobs/:id` 查看真实阶段、逐作业/逐关结果、受控诊断和费用，必要时请求取消。内部 `failed`、`uncertain`、`interrupted` 不会被改写成“已经完成”。状态未知时先用只读上游查询确认结果，再决定是否创建新任务；新课程任务会重新核对并跳过已满分作业。

管理员可对服务端明确返回 `can_retry=true` 的已结束作业调用 `POST /api/admin/jobs/:id/retry`，请求体为空或 `{}`。这与用户端重新执行使用相同的资格判断、原任务范围及 `retry-job:<原ID>` 幂等键，因此管理员和用户同时点击也只创建同一个后续任务。接口返回管理员任务 DTO（含 `owner_id`、`context`、`can_retry`、`can_recover`），并记录 `job.retry` 审计；客户端不能替换账号、课程、作业、模式或重试键。执行只使用原用户在服务器内存中仍有效的登录连接，绝不借用管理员的头歌客户端；原用户未登录或会话过期返回 `409 OWNER_LOGIN_REQUIRED`，账号当前无服务权限返回 `409 OWNER_ACCESS_REVOKED`。排队后开始执行时仍重新检查账号权限和登录时限。

管理页面只根据明确的服务端能力显示“重新执行”或“复核并继续”，提交请求时显示等待反馈并防止重复点击。已完成、执行中、考试、采集、单关维护及含有未知提交的嵌套结果不开放普通重试；未知结果继续使用独立复核流程。管理员能够发起原范围重试，不代表系统可以重新登录用户或把历史成绩视为当前完成证据。

未知提交的恢复入口是 `POST /api/jobs/:id/recover`，由服务端 `can_recover` 能力控制，与普通 `/retry` 分开。它创建保留原范围的异步子任务，以 `recover-job:<原ID>` 保证同一入口重复点击复用；先校验当前账号课堂、作业及完整成绩，再检查原结果中明确的不确定关卡。只有这些关卡已确认满分、选做或作业已截止，才进入正常执行流程。缺少原关卡身份时必须确认整份作业的必做内容完成；身份或成绩仍未知则不调用模型、不提交，保留进度和管理员诊断，子任务仍可再次复核。`POST /api/admin/jobs/:id/recover` 仅管理员可用，从服务器内存选择原用户未过期的会话，不使用管理员的头歌账号；用户连接过期返回 `OWNER_LOGIN_REQUIRED`。恢复请求记录到管理审计。

复核子任务带有服务端生成的原任务关联和公开状态投影。`queued`、`reconciling`、`continuing`、`blocked`、`completed`、`stopped` 分别显示为排队、正在复核、复核后继续、复核未通过、复核已完成和复核已停止；复核开始时复制原任务的公开进度，复核阻塞时保留原 13/19 等计数，用户不会看到短暂的零进度或内部诊断。

普通单文件代码在自测后校验编辑器内容失败，也可能留下 `uncertain`，但并未进入正式评测。恢复时会从同用户、原任务及关卡派生的幂等键读取持久执行记录，要求目标、候选代码哈希、快照契约和自测未知证据匹配，且记录没有正式评测结果或正式验证尝试；通过后才允许以新任务继续。终端、绘图、客观题、缺失证据或真正未知的正式提交不适用此判断。该证明不会提升候选答案状态，也不会改写历史任务。

历史正式评测曾把精确的“启动环境失败”返回保存为代码失败。对于完整终态、所有文件及提交哈希和题目契约匹配、只有该环境诊断且没有未知评测或真实代码失败的候选，普通单文件代码允许重新执行全部公开自测与正式评测，避免先调用模型改写源码。旧失败证据保留；只有新实际通过证据才能恢复题库可复用状态。终端、工作区评测、缺少公开样例或证据不完整的候选不适用。

模型请求默认总时限为 4 分钟（`MODEL_TIMEOUT` 可覆盖），包括收到 HTTP 200 后读取完整响应正文的时间。正文中断会在管理员诊断中区分 deadline、canceled、unexpected_eof 或 read，并记录收到的字节数与声明长度；超过 8 MiB 单独标记 response_too_large。诊断不记录响应正文、认证信息或原始传输错误。HTTP 200 正文中断仍保留未知计费预留，不自动重复付费请求；它也不是错误代码证据或 max_tokens 截断。

单文件求解中，增强模型明确出现 HTTP 200 正文 deadline 时，可在原次数、评测数、剩余预算与上下文内持久化一次降级决定：换用不同的常规模型、关闭额外推理并保留完整输出额度。旧调用仍记未知计费，下一次调用单独预留；此 run 后续已确认代码错误的修复保持降级模型，不再次进入同一超时模型。常规模型也断流、其他传输错误或平台提交未知时仍停止，不借降级重放平台操作。HTML 属性题的提示保留矛盾字面要求与绑定到源码的失败历史，要求保留已通过属性，避免在两个已失败值之间反复切换。

首页入口、样式和模块依赖按内容摘要加入资源修订号。文档 meta 与 API 的 `X-App-Asset-Revision` 使用相同摘要；已打开的新页面在常规 API 响应中发现修订变化会提示手动刷新，保留当前输入，不增加额外轮询或自动刷新。旧版页面须首次刷新后才具备此提示能力。

管理记录把单份作业故障和批次结束分开显示。例如合成批次中，第一份作业因清单不能唯一定位而未进入关卡，后面另一份作业的第 2 关执行到整批时限；列表不会把后者的关卡挂到第一份作业名下。需要跟进的作业各自保留具体原因，新批次持久化类型化 `stop_reason=time_limit / canceled`，管理摘要另有 `pending_homeworks` 说明尚未开始的作业数。历史记录没有类型化结束原因时，只有整批取消、最后执行作业中断且诊断明确记录 deadline，才展示 `deadline_observed`：“最后执行的作业记录了超时，整批已停止”；更早的子任务超时不会单独被解释为批次时限结束。批次停止不撤销此前完成结果，也不表示尚未开始的作业已经自测失败。

内部 `collect_verified` 使用独立、有界的采集执行通道，默认不设置整次扫描时限、分页数、课堂数、作业数、关卡数、累计请求数或累计流量上限。其他账号采集繁忙时保留在队列，不再以“繁忙已跳过”结束，也不占用答题 worker。进行中及已结束课堂的清单均读取到实际结束；只有明确遍历完且没有读取失败，才报告 `scan_exhausted=true / scan_complete=true`。单请求超时、单响应大小、只读白名单、速率控制、取消与账号权限检查保留。每次新的登录可发起新的完整扫描；同账号仍在进行的采集合并，显式幂等键仍然生效。历史达到限额的记录保留原状，不改写为全量完成。详细计数和历史记录解释见 [已通过答案采集](verified-collection.md)。

用户可在重新登录后，对符合条件的中断记录手动重新执行；服务不会自动跨重启恢复 worker 闭包，也没有后台管理员代替用户重新登录的实现。管理员禁用用户时，现有会话会失效并请求停止任务；这仍不能撤销上游已经受理的操作。身份和管理 API 见 [PLATFORM.md](PLATFORM.md)。


截止状态：用户端作业列表只展示仍可安排的作业。服务端优先使用头歌返回的 `已截止 / 已结束 / closed / ended` 状态，并按 `end_time / deadline / end_date` 的上海时间兜底判断；缺少日期不当作截止。补交作业只有在上游明确给出有效延长截止时间时才保留。`course` / `all` 任务在规划和每份作业开始前都会复核截止状态，已截止作业不会进入运行实例、模型调用或提交；执行中跨过截止时间时停止后续关卡。历史题库采集仍读取原始列表，以保留已完成作业的核验记录。

混合 Hadoop 工作区不是普通编辑器代码题：`hint.txt` 只保留平台占位内容，候选 shell 脚本通过同一运行实例的 `tab_type=4` 命令行执行。自测前只执行一次固定 `start-dfs.sh` 环境准备，并轮询 HDFS 根目录可用；准备失败时任务保持待核验，不生成新候选。之后正式评测使用原占位文件和 `tab_type=4` 的保存/构建链路。`game_status` 的运行阶段 1、2、3、4 和 HTTP 304 都是过渡读取；只有完整终态和测试证据才结束。


课程与全部课堂任务统一使用 `JOB_TIMEOUT` 控制整批上限，默认 2 小时，允许显式配置到 24 小时；`RunCourses` 不再另设固定 30 分钟截断。单份作业仍受 30 分钟保护，单次 HTTP 请求与模型调用保留各自超时，父级取消和用户停止继续传播。生产升级须同步检查环境配置：旧的 `JOB_TIMEOUT=30m` 会覆盖新默认值。
