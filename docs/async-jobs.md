# 异步课程执行服务

Web 请求只负责校验会话、入队和返回任务 ID。`cmd/web` 启动 `internal/jobs.Manager`，在同一个 Go 进程中运行有界 worker。浏览器不会启动 `cmd/educoder`，服务也不会用 `os/exec` 调 CLI。

当前用户界面面向服务交付：选择课堂或一键处理全部未完成作业，然后查看进度。创建任务使用 `POST /api/jobs`，响应是 `202` 与 `data.id`。客户端通过 `GET /api/jobs/:id` 查询，也可读取 `GET /api/jobs` 恢复自己的历史；`POST /api/jobs/:id/cancel` 请求停止后续执行，不能撤销已经到达上游的保存、提交或评测。

## 课堂与账号执行范围

```json
{"scope":"course","mode":"submit","course":"COURSE","idempotency_key":"CLIENT_GENERATED_KEY"}
```

```json
{"scope":"all","mode":"submit","idempotency_key":"ANOTHER_CLIENT_GENERATED_KEY"}
```

`course` 范围要求课堂标识，不接受 `homework_id` 或 `game`；`all` 范围不接受任何课堂、作业或 game 参数。后端从当前会话客户端读取活动课堂，并确认所选课堂归属。先解析完整清单，限制在 20 个课堂与 100 份作业内，再开始执行。

每份作业先读取完整且唯一的目标关卡得分；明确必做关卡数且全部精确满分才计为已完成并跳过，`finished_challenge_count`、`passed_count`、已提交标记不能代替逐关得分证据。上游明确标记为选做的关卡从执行计划、待完成数量、进度分母及最终核验中排除，不能仅根据 `challenge_score=0` 判为选做。全为选做的作业不计入 `total_homeworks`。剩余作业调用现有 `RunHomework`。某份作业失败或结果未知时记录 `needs_service` 并继续处理其他独立作业，不自动重复该作业的未知写入。

课程任务结果保留 `total_homeworks`、`completed_homeworks`、`skipped_homeworks`、`needs_service_homeworks` 和每份作业结果；completed 包含已完成而跳过的作业。管理员读取详细结果，普通用户只接收服务状态与进度摘要。整批最多 30 分钟，模型实际费用和未知预留共受 $2 内部预算约束；每份作业的 $0.50 上限仍保留，预算不是用户余额或计费套餐。

## 整份作业与单关维护模式

答题提交默认使用整份作业范围：`scope=homework`、`mode=submit`，请求不携带 `game`。服务先读取并严格校验这份作业的完整关卡清单，再按位置顺序处理必做关卡；选做关卡不进入题目求解、不调用模型、不保存或提交答案，也不列为失败或待处理。已经由当前作业进度精确证明满分的必做关卡会标记为 `skipped`。每个新提交后都会重新读取对应关卡进度，只有精确满分才进入下一关。结束前还会对全部计划必做关卡做一次最终满分核验，只有 `completed_levels == total_levels` 且 `failed_levels == 0` 才报告 `passed`。失败、预算耗尽、取消、清单不完整或结果待确认都会停止后续关卡并保留已完成结果。

为兼容已经打开的旧版浏览器页面，服务端也会把缺少 `scope`、但同时携带 `game` 的旧版 `mode=submit` 请求归一化为整份作业任务，并清除单关 `game` 字段；这类请求不会再退化为只执行一关。

作业可能只选择底层实训的一部分关卡；roster 读取以作业进度和 `challenge_count` 的交集为准，底层实训 header 中未被该作业选中的关卡不会阻塞批处理。客观题模型请求为答案 JSON 预留最多 8192 个输出 token，避免推理文本占满默认上限后把后续关卡误置为待复核。

每关每轮默认最多 10 次模型调用、10 次候选尝试；已确认的自测失败或未满分会把反馈交给模型修复。编程题提交任务在本轮次数耗尽后，服务端默认自动继续同一持久化运行，最多 4 轮，无需用户再次点击。继续运行保留失败源码哈希、样例反馈、历史候选、累计费用和未知计费预留，不重置作业的总费用或时间预算；每轮开始前重新检查作业仍可安排。已确认失败的相同源码不再次保存、自测或正式提交，模型会收到有界修复历史；当前编辑器代码不被当作不可修改的正确模板。正式提交结果未知、源码并发冲突、费用预算耗尽或作业截止时保持真实状态，不将其改写为通过。

模型输出截断或 JSON 无效会在剩余次数、费用和时间预算内自动重新生成；截断后的请求关闭可选推理并使用 8192 输出 token，防止反复占满额度。未知计费预留仍计入整份作业预算。自测比较规范 CRLF/LF，并忽略一次终止换行；内部空格、换行和答案内容仍须相同。仅被旧换行规则误拒绝的候选可重新完整自测，再进行正式评测，不直接标记通过。

批处理保留子运行的真实状态，`selftest_failed`、`attempts_exhausted`、`model_error` 不再统称为平台待复核。管理员结果每关包含 `reason_code`、`model_calls`、`max_model_calls`，用于排查停止位置和尝试次数。普通用户接口使用专门 DTO，展示处理进度和服务状态，不返回内部原因、模型调用次数、费用或原始事件；这些与早期调试工作台的公开结果不同。模型原始响应和自测原始内容不作为用户内容。保存、执行流或正式提交结果未知时仍停止自动写入，避免重复操作。

代码自测帧解码失败与正式提交未知使用不同原因。自测仅进行 `evaluate=0` 保存和运行流；当 `self_test_status=unknown` 且还没有正式 `evaluation` 时，原因码为 `selftest_stream_unconfirmed`，明确的 WebSocket 连接失败仍用 `selftest_connection_failed`。已有正式 `evaluation` 的未知结果保持 `submission_uncertain`，残留的自测消息不会把它误标成自测故障。两种情况都保留未核验状态，而不是把协议异常当成错误答案交给模型反复生成。批处理同时保留失败子任务实际提供的非空诊断，过滤空白并去重；不会再用 nil error 生成 `diagnostics:[""]` 而丢失子任务原因。

代码题未开放查看测试输入/输出时仍可正式评测。适配器只跳过输入和预期输出同时为空字符串的公开占位样例；没有公开样例时，`submit` 模式继续正式提交，`selftest` 模式返回 `selftest_skipped`。自测流支持标准及 URL-safe Base64、可选 padding 和 ASCII 空白，仍要求编码后的精确结束标记，不以任意明文兜底。正式轮询收到 `status=0` 时，只有明确失败结果（正的错误数、测试结果为 false 或编译失败标记）才进入已结束未通过的修复流程；裸状态码和缺失证据仍需只读核验，不重新提交。完整协议条件与原始 HAR、线上流核验和本地合成测试的证据区别见 [代码题协议说明](programming-protocol.md)。

Web 客观题执行会在生成前读取题干和选项中的真实图片，按题号、选项绑定给模型，不会要求模型仅凭图片地址猜题。图片仅在内存中处理；原地址（含签名查询）在持久化快照和模型文本中替换为内容 SHA-256 标记。下载限制为同源附件端点及已验证的官方图片存储重定向，不向图片存储转发账号认证；图片缺失、格式不支持或超限时，管理员诊断保留资源读取原因，用户看到服务处理中；不会提交信息不全的答案。

同一次执行保留最多 10 份已确认非满分的完整答案及得分，供模型复核；相同完整答案再次出现时跳过平台提交，但仍计入模型调用和费用。只有返回的逐题结果与本次题号、题名、类型、实际作答精确匹配，才把正确性反馈交给模型；不会根据总分推断单题对错，不会枚举选项或穷举答案。

仅生成答案或公开样例自测使用 `scope=current` 并携带 `game`，只处理当前关卡，不会继续同一作业的其他关卡。

默认配置为 16 个 worker、256 项队列、单账号 16 项待处理、单账号最多 4 个并行执行、模型并发 8、单任务 30 分钟。账号内同一目标仍只保留一个排队或运行任务；同一账号的不重叠作业可以并行，不同账号也可以并行。课程任务与该课堂的作业任务互斥，全部课堂任务与该账号的其他执行目标互斥；它们是不同请求，不会错误合并为相同幂等响应。模型并发是进程内同时发起的模型请求上限，实际供应商 RPM 仍由模型服务商账户限制。HTTP 请求取消只取消等待，不会取消已接受的后台任务。

任务状态、幂等键和公开进度保存在独立 SQLite 中。服务重启时将未完成任务标为 `interrupted` 或 `uncertain`，不会自动重放可能有副作用的保存或提交请求。owner 由服务端平台身份产生，再由任务存储哈希；旧登录名 hash 不会自动归属到新身份。Cookie、密码、模型密钥、`sec_key`、WebSocket 地址和模型原始响应不写入任务数据库。

模型密钥通过 `DEEPSEEK_API_KEY_FILE` 指定的 Docker secret 读取。空密钥时服务仍启动，浏览、课堂和任务功能可用；管理员容量中的 `model_configured` 为 `false`，创建普通作业执行任务收到统一的 `503 SERVICE_UNAVAILABLE` 服务提示。考试列表及已交卷摘要核对不需要模型，仍可使用；尚未提交的考试执行到需要生成答案时保留 `needs_provider`，不保存或提交答案。配置密钥后重启容器即可启用模型执行。

CLI 仍用于手动验证和运维调试，Web 任务不会为每次答题创建 CLI 进程。任务服务直接复用同一 Go 协议客户端、solver、objective taskservice 和题库连接，在 goroutine 中执行，并把状态写入可恢复任务记录。

## 在线考试范围

在线考试使用独立范围，不混入课堂实训作业或全部未完成作业批次：

```json
{"scope":"exercise","mode":"submit","course":"COURSE","exercise_id":501,"idempotency_key":"EXAM_REQUEST_001"}
```

浏览器通过 `GET /api/courses/COURSE/exercises` 读取考试元数据，使用同一 `POST /api/jobs` 与本人任务查询接口。服务在现有 worker 中直接调用 `RunExercise`，共享模型并发与费用账本。同账号同一考试不会并发覆盖答案；不同考试与实训作业的目标保持独立。幂等键按 owner 隔离，旧键重放不重新生成、保存或交卷。

服务先查本人交卷摘要。已交卷时只读摘要和 `common_header`，教师禁看完整试卷也能展示已交卷与公开成绩，不依赖模型。历史摘要的题目总数不等于本次已核验保存数，不能据此把全部题目计成已答。新执行在入场、监考、个人剩余时间和身份检查通过后，先生成并校验全卷，再逐题保存、回读，最后检查未答数并交卷一次；未知保存/交卷结果停止自动写入，仅做只读核对。已交卷、成绩待公布、已评分和精确满分分别表示，不保证提交即满分。

当前支持单选、判断和单空文本，缺少媒体内容或未知题型在写入前停止。单空回读结构由当前公开学生答题组件源码确认，实际保存仍必须重新读取服务端 `user_answer` 并逐字匹配；HAR 保存 ACK 本身不算回读证据。需要教师解锁、原站监考或专用客户端的考试保留原站流程。详情、字段及证据来源见 [在线考试协议](exercise-protocol.md)。


## 管理排障与恢复

普通用户不负责解读协议或模型报错。管理员通过 `/api/admin/jobs` 和 `/api/admin/jobs/:id` 查看真实阶段、逐作业/逐关结果、受控诊断和费用，必要时请求取消。内部 `failed`、`uncertain`、`interrupted` 不会被改写成“已经完成”。状态未知时先用只读上游查询确认结果，再决定是否创建新任务；新课程任务会重新核对并跳过已满分作业。

管理记录把单份作业故障和批次结束分开显示。例如合成批次中，第一份作业因清单不能唯一定位而未进入关卡，后面另一份作业的第 2 关执行到整批时限；列表不会把后者的关卡挂到第一份作业名下。需要跟进的作业各自保留具体原因，新批次持久化类型化 `stop_reason=time_limit / canceled`，管理摘要另有 `pending_homeworks` 说明尚未开始的作业数。历史记录没有类型化结束原因时，只有整批取消、最后执行作业中断且诊断明确记录 deadline，才展示 `deadline_observed`：“最后执行的作业记录了超时，整批已停止”；更早的子任务超时不会单独被解释为批次时限结束。批次停止不撤销此前完成结果，也不表示尚未开始的作业已经自测失败。

内部 `collect_verified` 是有独立读取上限的只读任务。没有读取失败且正常达到采集上限时，`succeeded` 仅代表本次分批扫描结束；`scan_complete=false` 和 `stop_reason` 明确说明未覆盖整个账号。已保存答案和重复计数保留，未知错误仍显示失败。该语义不适用于有副作用的答题提交，不会把自测或正式评测未知结果标为通过。详细计数和历史记录解释见 [已通过答案采集](verified-collection.md)。

当前没有持久化 worker 闭包、自动跨重启恢复执行、后台管理员代替用户重新登录或一键修复所有异常的实现。管理员禁用用户时，现有会话会失效并请求停止任务；这仍不能撤销上游已经受理的操作。身份和管理 API 见 [PLATFORM.md](PLATFORM.md)。


截止状态：用户端作业列表只展示仍可安排的作业。服务端优先使用头歌返回的 `已截止 / 已结束 / closed / ended` 状态，并按 `end_time / deadline / end_date` 的上海时间兜底判断；缺少日期不当作截止。补交作业只有在上游明确给出有效延长截止时间时才保留。`course` / `all` 任务在规划和每份作业开始前都会复核截止状态，已截止作业不会进入运行实例、模型调用或提交；执行中跨过截止时间时停止后续关卡。历史题库采集仍读取原始列表，以保留已完成作业的核验记录。
