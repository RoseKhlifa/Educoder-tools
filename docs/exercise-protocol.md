# 在线考试协议

在线考试使用独立的 `exercise_id` 与 `exercise_user_id`，不转换成实训作业、game 或关卡。协议客户端、应用服务和模型请求都在 Go 中；TypeScript 只负责浏览器界面。Web 任务直接在现有 Go worker 内执行，不创建 CLI 子进程。

## 应用接口

`GET /api/courses/COURSE/exercises` 读取当前账号课堂的考试列表和本人状态。服务先检查课堂归属，元数据查询最多同时读取 4 份考试。返回标题、题量、截止时间、是否已交卷、已公布成绩和是否可安排，不向普通用户返回题干、候选答案、内部故障、模型调用数或费用。

考试提交使用已有异步接口，下面均为合成标识：

```json
{
  "scope": "exercise",
  "course": "COURSE",
  "exercise_id": 501,
  "mode": "submit",
  "idempotency_key": "EXAM_REQUEST_001"
}
```

`POST /api/jobs` 返回 `202` 与任务 ID；`GET /api/jobs/:id` 查看本人结果。考试范围不接受 `homework_id` 或 `game`。课程与全部课堂的作业批次不会自动纳入在线考试。同账号同一考试的排队或运行请求合并到同一任务，不同考试仍可分别执行；考试与实训作业保持独立目标。

非空幂等键按服务端 owner 隔离，同一个键改选其他考试或执行模式会被拒绝。应用服务收到空键时自行生成随机键；客户端仍应在同一次请求重试时复用原来的键。服务重启或重放旧键不会自动重复保存或交卷。

## 已交卷读取

服务先读取 `exercise_users` 的本人答卷摘要。确认 `commit_status=2` 后，仅通过 `common_header` 读取标题、题量和卷面满分等元数据，不需要再次读取完整试卷、入场、配置模型或写入答案。教师禁止交卷后查看试卷时，这条路径仍然可用。

`student_commit_status` 不能替代本人答卷的 `commit_status`。已交卷、已公布得分、精确满分是三个不同状态：只有成绩明确开放且得分为有效十进制数时设置 `score_known`；只有公开得分与已确认的正数卷面满分精确相等，才报告 `fullscore`。卷面满分本身不是本人得分。

历史摘要没有逐题作答证据，不臆造“全部题目已保存”。`completed_questions` 只累计本次执行中实际保存并成功回读一致的题目；历史已交卷摘要可保留该计数为 0，界面应显示“已交卷 · 共若干题”，而不是把 0 解释为没有交卷。

## 支持的题目与保存结构

当前全卷必须由下列已实现类型组成；未知、多选、多空、简答、实训和编程考试题型在首次模型调用或保存前停止。含尚未核验媒体内容的题干、选项同样停止，模型不会只根据资源地址猜题。

| 原站类型 | 模型类型 | 保存值 |
|---|---|---|
| `0` | `single` | 当前题目中真实的选项 ID |
| `2` | `judgment` | 当前判断题真实选项 ID，不固定假定真假顺序 |
| `3`，且只有一个空 | `fill_blank` | 槽位 `1` 与原始文本 |

选择类保存到 `POST /api/exercise_questions/QUESTION_ID/exercise_answers.json`，保留显式 `answer_text:null`：

```json
{"questionId":601,"exercise_choice_id":9009,"answer_text":null}
```

单空保存保留大小写、标点和有意义的空格，不使用字母选择题的大小写规范化：

```json
{"questionId":602,"exercise_choice_id":1,"answer_text":"CaseSensitiveValue"}
```

模型必须一次给出全卷完整候选。类型化校验检查题目完整且唯一、题目与类型一致、选项属于原题、文本答案非空，并拒绝未知字段、重复 JSON 键、额外 JSON、字母或选项位置代替真实 ID，以及混合选择/文本 payload。完整候选通过校验、题纸内容再次读取一致后，才开始逐题保存。

## 回读、交卷与不确定状态

保存成功 ACK 仅说明接口接受请求，不证明答案已经回读一致，更不证明正确性。每题保存后重新读取题纸，并在交卷前再次读取完整题纸检查全部值。题目、选项或考试尝试身份变化时停止写入。

选择类按题纸选项的 `user_answer_boolean` 确认恰有一个匹配的选项。单空题按下列明确结构确认，槽位必须是数字 `1`，文本必须逐字相同；空数组、重复槽位、重复字段、未知字段或其他形态均返回 `answer_readback_unconfirmed`，不继续交卷：

```json
[{"choice_id":1,"answer_text":"CaseSensitiveValue"}]
```

上述单空回读结构来自当前公开的原站学生答题组件源码：渲染器从 `user_answer` 按 `choice_id` 找到 `answer_text`，保存成功回调写回同样的对象。用户提供的 HAR 证明了按题保存和交卷的请求及 ACK，但没有包含完整保存后题纸。因此，源码用于确定解析结构，真实执行仍必须用服务端新读到的值确认保存，不能以本地回调或 mock 代替回读。

全部保存回读一致后，调用 `begin_commit`。`question_undo`、`shixun_undo`、`oj_undo` 必须均为 0 且字段完整，才发送一次 `commit_exercise`：

```json
{"categoryId":"501","commit_method":1}
```

交卷响应丢失或不完整时，仅重新读取本人答卷摘要核对，不自动再次发送交卷。未确认时保留 `verification_unconfirmed / submission_uncertain`，不会修改成已完成。重新使用旧幂等键也只做只读核对，不重复模型生成、答案保存或交卷。

## 入场、监考和个人计时

保存与交卷前都会重新验证考试归属、本人身份、当前尝试、入场状态、个人剩余时间和保护配置。当前账号已锁、需要教师解锁、尚未入场、字段缺失或仍需原站监考/专用客户端时，返回 `action_required` 等真实原因。`is_locked` 的被动配置与 `is_user_locked / start_locked` 的实际锁定分开处理。

当前没有猜测或自动执行 start、unlock、切屏记录、摄像、身份核验、IP/设备限制绕行等请求。需要这些动作的考试保留原站学生与教师流程。`only_on_client`、网络或白名单、虚拟环境、切屏、截图、摄像、身份、IP 等保护由协议 guard 一并检查。

个人计时使用 `exercise_time.left_time` 与 `user_end_time`。个人截止可为 RFC3339 或 `yyyy-mm-dd HH:mm:ss`；后者固定按上海时间解析，不继承服务器时区。较晚的 `user_total_end_time` 或考试全局截止不用于延长个人时间。

## 持久化与验证

考试复用题库 Store 的运行记录和使用量账本，不把“保存成功”或“已交卷”提升为题库正确答案。运行 checkpoint 只保存公开结果、目标及写入边界，题干、候选答案、Cookie、密码、解锁码、监考凭据和签名资源地址不进入任务结果。

模型调用前持久化调用次数与费用预留；已知计费结算实际费用，未知计费保留预留，不按零费用处理。数据库 checkpoint 或用量落盘失败有独立原因码，停止后续写入。

测试分别覆盖协议 HTTP mock、类型化模型候选、整卷单选/判断/填空的保存回读与一次交卷、错误回读停止、已交卷禁看题纸、未知交卷只读核对、幂等隔离和账本。真实已交卷考试仅做只读核对，没有重新开始、修改作答或重新交卷；模拟成功不是新的线上交卷证明。
